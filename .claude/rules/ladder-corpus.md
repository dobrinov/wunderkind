# The ladder corpus and problem files

**The arithmetic facts come in two sizes.** `db/seeds/arithmetic_facts.yml` is every pair (7,646 rows) and was never imported into production; `db/seeds/arithmetic_facts_core.yml` (954 rows) is what production gets, written by `ruby tools/arithmetic_facts_core.rb` from the full file: every sum and difference within 20, the 10x10 table and its division facts, every tens-and-tens fact, and 50 rows of each other two-digit skill spaced across its ratings. The full file would put about four bare sums beside every other problem at Elo 600-900 and spread a small user base too thin for those ratings ever to calibrate. Rows are verbatim, so importing the full file later only adds the rest; never edit the core by hand.

The ladder corpus is built by `tools/authoring` (see its `README.md` for the commands and `PROBLEM_TYPES.md` for the catalogue of problem types and the recipe for adding more of each), which runs outside Rails: the app still has no question generator in it and never makes a question at runtime. A *family* there is one type of problem written at six rising Elo ratings with a few variants each, so a student who cannot do a type meets the same type lower down and climbs back up as their rating recovers — `spec/services/ladder_corpus_spec.rb` guards that property, along with answer parseability, figure files and explanation depth. Rebuild with `ruby tools/authoring/build.rb`, then `tools/authoring/rasterize.sh` (headless Chrome turns the figure SVGs into PNGs — Active Storage will not serve SVG inline), then `ruby tools/authoring/check.rb`, which validates answer parseability, widget shapes (values on the step grid, points inside the plane, bins that are not empty), figure files and explanation depth, and re-solves from its text every puzzle whose answer a search can confirm (`solve_again`: the AB + BA count, the digit difference, hidden digits, weighings, the domino boards via `lib/tiling.rb`, the nearest tick, the `pick.*` judgements, the boundary item a two-bin sort has no bin for, and every magic square, pyramid and Latin table via `lib/uniqueness.rb`, which the generators also call before keeping a puzzle) — a widget grades against one stored answer, so a problem with two right answers marks one of them wrong, which a dozen families shipped before that check existed. It refuses two options that are the same answer (a product with its factors swapped, or one number written two ways) — `rat.factor_trinomial` shipped nine problems that marked (x + 20)(x + 19) wrong beside (x + 19)(x + 20). Rebuilding one family with `build.rb <prefix>` rewrites its whole area file with that family alone, and a full build without `tmp/authoring/existing.txt` picks different variants elsewhere, so a fix to one family is spliced into the committed files by matching problem text. It also refuses an explanation that never mentions a fraction the problem shows, which is what an explanation written for 2/4 looks like when the text reduced it to 1/2. A family written but not ready carries `held: "why"`: the build skips it and prints the reason, so a full rebuild reproduces the committed files rather than quietly adding a thousand problems nobody reviewed. Figures are drawn to scale from the numbers in the question, and every number in a figure is repeated in the text because the views render question images with an empty `alt`.

Note that `problems:export` thins to `MAX_PER_SHAPE` per template and drops images and `family`, so an export is not a backup of the fact tables or the ladder corpus — re-import the files instead. `rake problems:export` writes the database back out (problems to `db/seeds/problems.yml`, the topic tree to `topics.yml`). `rake problems:stats` reports the distribution. The earlier parametric generator was removed for producing near-duplicates; the ladder builder answers that with families whose variants are capped per rung and deduplicated against the whole corpus and the existing bank.
