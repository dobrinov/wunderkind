# Frontend and the design system

Frontend: Turbo + Stimulus (controllers in `app/javascript/controllers`, registered in `index.js`), esbuild, Tailwind v4 (design tokens in `@theme` in `app/assets/tailwind/application.css`; every component rule lives in `@layer components` so a utility in the markup wins over what the component `@apply`s — unlayered rules outrank all utilities and used to silently beat them). **One of each**, because an audit found two neutral ramps in 31 files, two button families restyled at a dozen call sites and five tab styles: the one neutral is `ink-*` (Tailwind's `gray` is switched off in `@theme`, so a `gray-*` class simply does not exist); buttons are `.button` + `button-primary` (the tactile key, one per screen) / `button-secondary` / `button-quiet`, plus `button-white` on indigo, `button-danger` and the size `button-large` — never restyled with radius, weight or padding utilities at the call site; `.link-cta` is a standalone text link with a 44px target; `.segmented` is the one tab strip (with `.segmented-count`); `.list-row` is a whole-row link (icon tile, title, one line, chevron); `.switch` is the one on/off control and `.field`/`.field-hint` label a form field; selects draw their own chevron. The one decoration is the maths-signs tile (`images/math-tile.svg`, `-ink` for indigo grounds, drawn as strokes because an SVG used as an image cannot load Nunito): `.math-paper` covers the auth pages, `.math-hero` sits behind the landing hero, `.math-fade` / `.math-fade-ink` fade it out of a corner on the welcome before placement, a session summary, the empty family page and the „Днес" hero — places a child arrives or celebrates, never behind a problem, where a sign could be read as part of the question. Every email carries the same tile as a PNG band (`public/mail/math-band.png`, since mail clients strip SVG) at the top of `layouts/mailer`, which also gives each email a heading (the subject unless the template sets `:heading` or fills `:band`) and builds buttons with `EmailHelper`. Text sizes are named steps in `@theme` — `text-micro` 11, `text-caption` 12.5, `text-meta` 13, `text-sm` 14, `text-ui` 15, `text-base` 16, `text-lead` 17, `text-lg` 18, `text-xl` 20, `text-title` 22, `text-page` 28 — and radii are 10/12/14/20/24, where views used to pick from twenty-six arbitrary sizes and seventeen radii; only the public marketing pages keep arbitrary editorial sizes. Everything a finger presses is at least 44px and every input is 16px (Safari zooms into smaller ones), because this app is used on tablets. The layouts scroll the document, not an inner `<main>` — iPad Safari only collapses its toolbars when the page scrolls — with the header, practice header and tab bar `sticky`. Note esbuild's entry glob is `app/javascript/*.*`, so shared JS helpers go in a subdirectory (`app/javascript/lib/`) or they become their own bundle. The build minifies and code-splits: `math` (KaTeX — most of the JS) is not imported by `controllers/index.js` but handed to `registerLazy` (`lib/lazy_controllers.js`), which fetches a controller's chunk the first time an element names it and registers it then, so a page with no maths downloads none of it; a new controller with a heavy dependency belongs there too. Chunks are named `*.digested.js` so Propshaft serves them under the name the bundle imports them by instead of fingerprinting them a second time. Students type a numeric answer (`numeric_answer`: the accepted value parses with `ExactValue`, which is every exact-value question in the bank — integers, decimals and fractions, nothing else) on **our own number pad** (`answers/_number_pad`, `number_pad_controller.js`, demoed on `/design-system` under „Отговори"), which replaced MathLive: MathLive put most of the app's JavaScript, an English ☰ menu and a shift layer of „■⁷", ∞, Σ and ± in front of a child typing 12, and its keypad vanished on an iPad after „Следващ". The field is a drawn `role="textbox"` rather than an `<input>` — an input would raise the system keyboard on a tablet and could not set a fraction stacked while it is typed — holding a plain string that is exactly what lands in the hidden `value` (`12`, `0,75`, `-3/4`). It draws the one fraction stacked with an empty box where the next number goes, a caret a tap can move, and nothing that is not part of a number: the keys are digits, a decimal comma, a minus that toggles the sign (an answer is a number, never a sum) and a fraction key that works like the problem editor's, and a physical keyboard types the same set (`.` becomes `,`, `/` and `:` are the bar), so „8 евро" or „x=72" cannot be typed into a numeric answer to be marked wrong for their wording. An empty answer is stopped in the browser with „Първо напиши отговора си." instead of reaching the server. On a phone the digits go in two rows of five with the signs, fraction and delete under them (three rows of 48px instead of four, placed by `grid-template-areas` keyed on each key's param), because the four-row pad pushed „Отговори" below the fold of an iPhone; docking the pad to the bottom of the screen was tried and covered the whole problem on an iPhone SE. The pad and the scratchpad are `user-select: none` with no `-webkit-touch-callout`: in real Mobile Safari a finger held and drawn across the paper selected the whole sheet and raised „Copy · Look Up". Its keys use the plain editor's touch two-step (`keepFocus`/`tap`); note that Stimulus reads `data-number-pad-key-param="7"` as the *number* 7, which is why `press` stringifies it. `ExactValue.parse` still unwraps MathLive's `(1)/(2)` serialization, harmless now that nothing produces it. `answer_form_controller` claims Enter in the capture phase (the number pad and a widget keep their state in a hidden field with no implicit submission), except in a textarea, where it stays a newline and ⌘/Ctrl+Enter submits, and on the single-choice grid, where the form has no submit button because the option button *is* the answer. KaTeX CSS/fonts are vendored in `app/assets/stylesheets`. The design system lives at `/design-system` (open in development, admin-only in production). No system tests are generated for this app.

**Installable app (PWA).** `app/views/pwa/` holds the manifest (`/manifest.webmanifest`, copy from `pwa.description`/`seo.brand_title`, white theme to match the header, 192/512 icons plus maskable ones in `public/`, start URL `/?source=pwa`) and the service worker (`/service-worker.js`, both through `Rails::PwaController`, registered by `lib/pwa.js`). The worker does only two things: digested assets (`/assets/*-<hash>.*`, `*.digested.js`) come cache-first from `wk-assets`, trimmed to the newest 120 — safe because their names change with their content, and it lets a page from the previous release still find chunks after a deploy — and a navigation that fails on the network gets `public/offline.html` (self-contained, reloads itself on `online`). HTML is never cached, since nearly every page is one person's; POSTs, Turbo fetches, polling and cross-origin requests pass through. A Turbo Drive visit that fails offline needs nothing extra: Turbo's BrowserAdapter retries it as a full navigation, which the worker answers. Bump `VERSION` in the worker when `offline.html` or the strategy changes. „Аз" ends with „Wunderkind на началния екран" (`profiles/_install`, `install_controller.js`), rendered `hidden` and shown only where installing is possible and has not happened: Chromium's `beforeinstallprompt` (kept by `lib/pwa.js`, since it can fire before the row is on the page, and not `preventDefault()`ed, so Chrome's own banner still shows) opens the native prompt; an iPhone or iPad (iPadOS reports a Mac with touch points) opens a dialog with Safari's steps, drawn with Safari's icons because the labels follow the device's language; any other browser never sees the row.
