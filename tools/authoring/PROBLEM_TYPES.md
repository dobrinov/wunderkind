# Problem types in the bank, and how to make more of each

This is the working reference for the shipped question corpus: what kinds of
problem exist, what each kind is *for*, and the recipe for adding more of it.

The corpus lives in `db/seeds/ladders/*.yml` and is generated by
`tools/authoring` (see `README.md` for the build commands). Today it holds
**22,543 problems in 522 families**, Elo 600–2800:

| answer format | problems | what it is good for |
|---|---|---|
| interactive widget | 12,504 | anything the student can *do*: place, shade, sort, fill, match |
| typed exact value | 9,166 | one number, checked with `ExactValue` (fractions ≡ decimals ≡ percents) |
| multiple choice | 790 | symbolic or verbal answers a typed field cannot compare |
| with a figure | 849 | geometry, charts, number lines, solids — drawn to scale from the numbers |

## 1. The unit of authoring is a *family*, not a problem

A family is one **type** of problem, written once, at six or seven rising Elo
ratings, with several variants per rung:

```ruby
Authoring.family "pct.of_amount", topic: "Проценти", area: "fractions",
                 rungs: [ 970, 1060, 1150, 1240, 1330, 1430 ], variants: 6 do |c|
  pct  = c.pick(c.by_level([ [ 10, 50 ], [ 10, 20, 25, 50 ], ... ]))   # difficulty
  base = c.int(c.by_level([ 2..12, 2..20, 4..40, ... ]))               # rises per rung
  c.q(text: "...", answer: Num.ans(base * pct / 100), explanation: Explain.build(...))
end
```

Everything else in this document is a catalogue of what can go in the block.

**Rung rules** (enforced by `spec/services/ladder_corpus_spec.rb`):
at least 4 rungs, at least 300 points from bottom to top, never more than 150
points between neighbours, and no empty rung. Close rungs are the point: a
student who fails a type drifts *down that type's ladder* rather than out of it.

## 2. Answer formats and when to use which

| format | use it when | how to write it |
|---|---|---|
| `answer:` | the answer is a single number | `answer: Num.ans(value)` — ASCII minus, comma decimals, fractions as `3/4` |
| `answer:` + `tolerance:` | the answer is rounded (anything with π) | `tolerance: "0.05"` |
| `options:` | the answer is symbolic (`(x+3)(x−2)`), verbal (`да`/`не`), or a formula | 3–4 options, distractors = real mistakes |
| `widget:` | the student should *act*, not type | see the catalogue below |
| `figure:` | a diagram carries part of the information | `Figures.*`, and repeat every number in the text |

Rule of thumb: **numeric → typed, symbolic → options, procedural → widget.**
A typed field compares strings when it cannot parse a number, so `x = 3` or
`2√3` typed by hand will be marked wrong. Never ask for those.

## 3. The interactive catalogue (12 widgets)

Each widget is `WidgetKit.<builder>` in the authoring tool, a checker in
`app/services/widgets.rb`, and a Stimulus controller under
`app/javascript/controllers/widgets/`. Counts are problems currently shipping.

### 3.1 `blanks` — one or more numbered boxes (3,782)
For answers that have **two halves**: both roots, x and y, quotient and
remainder, perimeter and area, НОД and НОК, period and last digit.

```ruby
widget: WidgetKit.blanks([ [ "q", "частно", quotient ], [ "r", "остатък", rest ] ],
                         prompt: "#{dividend} : #{divisor}")
```
*More of it*: any procedure whose method has two outputs. Each field is graded
with `ExactValue`, so `1/2` and `0,5` both pass; pass `tolerance:` for rounded
values. Do not use it for one number — that is a typed answer.

### 3.2 `multi_select` — choose every option that fits (2,011)
For properties that must be judged option by option: divisibility, primality,
equivalent fractions, valid triples, true statements, losing positions.

```ruby
widget: WidgetKit.multi_select([ [ "34", false ], [ "45", true ], [ "51", true ], [ "62", false ] ])
```
*More of it*: pick a property, generate 2–3 numbers that have it and 3 near
misses. **The stem must list the options** (`"Кои от числата 34, 45, 51, 62 ..."`)
— the importer keys questions by their text, so a fixed stem collapses the whole
family into one problem.

### 3.3 `grid_fill` — a table with holes (1,046)
Magic squares, Latin squares, times tables, function machines, place-value
tables, two-way frequency tables, column addition, cross-number puzzles.

```ruby
widget: WidgetKit.grid_fill(rows: [ [ 8, nil, 6 ], [ nil, 5, nil ] ], answers: [ [ 8, 1, 6 ], [ 3, 5, 7 ] ],
                            column_headers: %w[…], row_headers: %w[…])
```
*More of it*: any structure with a **checkable constraint** — rows summing to a
constant, each symbol once per row, a rule linking input to output. Keep grids
at most 5×5 and blanks at most ~8, or the widget stops being a maths exercise.

### 3.4 `categorize` — items into named groups (1,124)
Prime/composite, even/odd, terminating/repeating decimals, acute/obtuse,
possible/impossible, growing/shrinking, winning/losing.

```ruby
widget: WidgetKit.categorize(bins: [ [ "p", "просто" ], [ "c", "съставно" ] ],
                             items: [ [ "i1", "17", "p" ], [ "i2", "21", "c" ], … ])
```
*More of it*: any binary or ternary classification whose rule is worth stating.
Every bin must get at least one item, and the stem must name the items.

### 3.5 `matcher` — pair the two columns (1,021)
Fraction ↔ percent, expression ↔ value, shape ↔ formula, equation ↔ root,
number ↔ binary, event ↔ probability, action ↔ inverse action.

```ruby
widget: WidgetKit.matcher([ [ "1/4", "25%" ], [ "1/2", "50%" ], [ "3/4", "75%" ] ])
```
*More of it*: any one-to-one correspondence with 3 pairs. Labels must be
distinct on both sides, or two answers become right at once.

### 3.6 `coordinate_plot` — click lattice points (835)
Plot a point, complete a rectangle, reflect/translate, mark the midpoint, plot
the intercepts, plot the solution of a system, plot a data point.

```ruby
widget: WidgetKit.plot(points: [ [ 2, 1 ] ], fixed: [ [ -3, 2, "A" ] ], x_range: (-5..5), y_range: (-5..5))
```
*More of it*: anything whose answer is a **position**. The order of placement
never matters; keep every solution point inside the range and off the given
points.

### 3.7 `grid_shade` — colour cells on squared paper (849)
Two modes. *Exact set*: complete a symmetry, mark a knight's moves, shade one
colour class of a chessboard. *Count only*: shade 3/8 of the grid, shade a
figure with area 12, shade 40%.

```ruby
widget: WidgetKit.grid_shade(rows: 4, cols: 8, cells: [ "0,1", "1,2" ])   # exact
widget: WidgetKit.grid_shade(rows: 4, cols: 10, count: 12, given: [ "0,0" ]) # any twelve
```
*More of it*: area and fraction models at the bottom of the ladder; tilings,
parity and colouring arguments at the top.

### 3.8 `ordering` — arrange in sequence (588)
Numbers, negatives, decimals, fractions, mixed notations, powers, measures,
probabilities, steps of a solution, figures by area.

*More of it*: any set with a total order; 3–5 items. Include the items in the
stem for uniqueness.

### 3.9 `number_line` — place a point (459)
Integers, negatives, decimals, fractions, the result of an operation, a rounded
value, the midpoint, a percentage of 100.

*Constraint*: `(max − min) / step ≤ 40` and the answer must sit **on** the step
grid, or the student cannot place it. `check.rb` enforces both.

### 3.10 `clock_hands` — set the time (387)
Read/set a time, elapsed time forwards and backwards, half hours, arithmetic
modulo 12.

### 3.11 `angle_dial` — turn a ray (299)
Set an angle, its complement or supplement, the third angle of a triangle, an
exterior angle, a polygon's interior angle, the angle between clock hands.

*Constraint*: the answer must be a multiple of the dial's step (5° by default;
use `step: 1, tolerance: 2` for angles like 108°).

### 3.12 `fraction_bars` — shade parts of a strip (194)
The first fraction model: shade 3/4, an equivalent fraction, a percentage, a
decimal, the remainder, a sum of like fractions.

## 4. The written-answer catalogue

These are the older, typed families (`arithmetic`, `numbers`, `fractions`,
`geometry`, `logic`, `word_problems`, `algebra`, `functions`, `advanced`), all
built the same way. Type groups worth knowing:

* **Written algorithms** — column addition/subtraction/multiplication/division,
  with the carry or borrow spelled out in the explanation.
* **Context problems** — shopping, sharing, saving, tickets, recipes, reading.
  Names, goods and containers come from `Props`; keep verbs gender-neutral
  (aorist, no participles), and avoid possessive pronouns.
* **Reverse problems** — from part to whole, from area to side, from sum to
  addend. These are the rungs that catch students who only know the forward move.
* **Two-step problems** — "of the remainder", successive discounts, buy-then-share.
* **Formula work** — perimeter/area/volume, Pythagoras, similarity, circle,
  progressions, derivatives.
* **Classification and comparison** — which is bigger, which fits the rule.
* **Estimation** — round, then compute; the explanation must say how far off it is.

## 5b. Types taken from competition papers

These came from problems pasted in one at a time and generalised into ladders.
Two of them need a **solver**, not just a formula: the builder enumerates every
candidate and keeps the problem only if the answer is forced. That is the rule
for any deduction type — a puzzle with two answers is not a puzzle.

| type | widget | family | how the builder guarantees it |
|---|---|---|---|
| who-is-who from a fixed tally ("three solved 3, two solved 2") | multi_select, categorize, blanks | `deduce.minority_group`, `deduce.assign_all`, `deduce.two_people` | enumerates all assignments of the tally, keeps the ones where exactly one satisfies the clues; the explanation is produced by *deducing*, and a puzzle whose derivation the narrator cannot finish is dropped |
| circular seating, forced neighbours | multi_select | `logic.circle_neighbours` | enumerates all seatings (rotations collapsed, reflections kept — the clues say clockwise); asks only about a person whose neighbours are the same in every surviving seating, and only about someone the adjacency clues do not name |
| two kinds of creature, two attribute totals | blanks | `logic.two_creatures` | searches for other non-negative integer solutions and rejects the problem if one exists |
| extremal share ("each ate at least 2 — how many could one eat?") | blanks | `logic.extremal_share` | asks for the others' minimum *and* the maximum, so the method is visible |
| digit product and the zero trap | blanks, multi_select | `digits.sum_and_product`, `digits.zero_product_pick` | zeros get commoner up the ladder; the `watch` line changes depending on whether this variant contains one |
| counting under digit constraints | blanks | `count.digit_choices` | asks for both factors and the product — the multiplication principle made explicit |
| Latin square drawn with ladybugs, one line of it asked | figure + blanks | `puzzle.ladybug_square` | enumerates every Latin square consistent with the clues and keeps the problem only if the asked cells hold the same ladybug in all of them — the grid itself may still have several completions, because it is the *question* that has to have one answer; then re-derives the answer by row/column elimination aimed at the asked cells, and drops the problem if that narration cannot finish, so the explanation is the chain the builder actually walked. Difficulty is the length of that chain — how many cells outside the asked line have to be filled first — not the size of the grid, which stops at 4x4 |
| arithmetic on pictures (lines, not parts) | figure + typed | `fig.square_line_equation` | the explanation contrasts counting lines with counting parts, which is where the trap is |
| row with a neighbour condition ("each child stands between a girl and a boy") | blanks, grid_shade, multi_select | `logic.row_between`, `shade.row_between`, `pick.row_possible` | the condition is on a child's *neighbours*, so positions two apart alternate and the row splits into two chains; even lengths give one row, n ≡ 1 (mod 4) forces the count but not the row, n ≡ 3 (mod 4) is impossible — one problem, three rungs of reasoning |
| age with a time shift | blanks | `logic.age_shift`, `logic.age_sum_shift` | going back to the present *before* using the sum; the second family isolates the trap that a sum of k ages grows by k·years |
| most items within a budget | blanks, multi_select | `logic.max_items_budget`, `pick.affordable_sets` | greedy from the cheapest, with the leftover money asked for so the method shows |
| exact payment from given coins | multi_select | `pick.exact_payment` | subset sums of the coin multiset; coin sets are chosen without a 1 so some amounts are genuinely unreachable |

**Clue kinds available to the deduction builder**: direct ("X solved 3"),
negative ("X did not solve 3"), comparison ("X solved more than Y"), equality
("X and Y solved the same"), difference ("X and Y solved different amounts"),
and for circles "X stands immediately after Y" and "X and Y are not neighbours".
Clues may share people — forbidding that makes whole configurations impossible.

## 6. The figure catalogue

`Figures.*` (in `lib/figures.rb`) draws: number lines, fraction strips, grids,
dot arrays, tape diagrams, bar charts, pie charts, spinners, tables, clocks,
triangles (from sides *or* from angles), quadrilaterals with heights,
L-shapes, circles with sectors, angle pairs (vertical, supplementary, around a
point, parallel + transversal), single angles, regular polygons, similar
triangles, segment chains, coordinate planes with lines and parabolas, cuboids,
cylinders, cones, spheres, prisms, pyramids, nets, Venn diagrams, growing
patterns and ladybug Latin squares (`ladybug_square`, whose `ladybug` helper
draws a bug with 1..5 spots at any scale).

*More of it*: add a builder that returns `Svg.canvas(w, h) { |c| … }`, then use
it with `figure:`. Two rules: **draw to scale from the numbers in the question**
(a 56° angle must look like 56°), and **repeat every number in the text**,
because the views render question images with an empty `alt`.

## 7. Recipe: add a family

1. Pick the file by area (`families/interactive_number.rb`, `families/geometry.rb`, …).
2. Choose a topic from `db/seeds/topics.yml` (the tree is fixed; no new topics).
3. Choose rungs: start where the type first makes sense, step 60–150 points.
4. Draw parameters with `c.by_level([...])` so difficulty rises with the rung.
5. Reject impossible or silly draws with `raise Authoring::Duplicate` (a ladder
   with a 178 m ladder in it is worse than a shorter ladder).
6. Write the explanation with `Explain.build(idea:, steps:, answer:, check:, watch:)`.
   `watch:` names the mistake the problem is designed to catch — the student
   only ever sees the explanation after getting it wrong.
7. Add a hint ladder with `hints: [...]` — 2–3 rungs, cheapest nudge first, and
   **none of them the answer**. A hint is read *instead of giving up*, an
   explanation *after* getting it wrong; they are not the same text at two
   lengths. The shape that works: the rule or method (no numbers), then the
   first concrete move with this variant's numbers, then the last rung that
   leaves exactly one step for the student. `check.rb` rejects a rung that
   contains the typed answer, or that names a blank and its value close
   together. Imported ladders reach students without further review, so a
   leaked answer ships silently — write the rungs as questions where you can
   ("колко остава за тази клетка?") rather than as statements.
8. Rebuild, check, import:

```bash
ruby tools/authoring/build.rb          # regenerate the YAML
tools/authoring/rasterize.sh           # only if figures changed
ruby tools/authoring/check.rb          # validation
bin/rails problems:import FILE=db/seeds/ladders
bundle exec rspec spec/services/ladder_corpus_spec.rb
```

## 8. Recipe: add a widget

1. Checker + display in `app/services/widgets.rb` (the solution must be
   decidable from the submitted state alone).
2. Stimulus controller in `app/javascript/controllers/widgets/`, registered in
   `controllers/index.js`. Leave the hidden `state` field **empty until the
   answer is complete** — that is what keeps the submit button honest.
3. Partial in `app/views/widgets/_<key>.html.erb`; shuffle anything whose order
   could leak the answer.
4. Hints in `config/locales/app.bg.yml` and `app.en.yml`.
5. A demo in `app/views/design_system/show.html.erb`.
6. Specs in `spec/services/widgets_spec.rb`; validation in `tools/authoring/check.rb`.
7. A builder in `tools/authoring/lib/widget_kit.rb`.

The admin form can only build `QuestionFormParams::EDITABLE_WIDGETS`
(number line, ordering, fraction bars). Questions using the other widgets keep
their grading when edited in the form, so nothing is lost — but the parameters
are meant to be generated, not typed.

## 9. Quality rules (what `check.rb` and the specs enforce)

* **Unique text.** The importer keys questions by their text; two problems with
  the same stem are one problem. Put the numbers in the stem, always.
* **Parseable answers.** Typed answers must match `ExactValue`'s grammar.
* **Distractors are mistakes**, not noise: the off-by-one, the forgotten carry,
  the sum instead of the product.
* **Explanations**: at least 120 characters, numbered steps, a check line, and
  where possible a `watch` line.
* **Typography**: `−` (U+2212) in text, ASCII `-` in answers, decimal comma,
  `·` for multiplication, `:` for division.
* **Realism**: no 178 m ladders, no cyclists at 140 km/h, no ten-hour films.
  Cap the ranges instead of letting the top rung run away.
* **Reachability**: number-line answers on the step grid, dial angles on the
  dial's step, plot points inside the plane, grid counts inside the grid.
